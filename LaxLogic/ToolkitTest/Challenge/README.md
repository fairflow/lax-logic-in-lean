# Challenge set

Four proved theorems from the development, re-stated with `sorry`. Generated by
`prover-toolkit/challenge.py --punch`; rationale in
`docs/toolkit-test-design.md`.

**Do not consult the original proof before attempting one.** Provenance is in
`../challenge-manifest.json`, which holds no ground-truth proofs.

## How these are built

Each challenge file is **16–18 lines** — header, one `import`, the namespace
and `open`s that were in force, the verbatim statement, `sorry`. It can be read
in full without learning anything.

Everything the original module had in scope arrives by importing
`../Punched/<Module>.lean`: that module with the challenge targets *deleted*,
and with the deletion closed under reverse dependency so it still compiles.
What survives is strictly more than a prefix truncation would give — a prefix
also drops every later declaration that was independent of the target.

| filter | rules out |
|---|---|
| external citation | a target that needs nothing the challenge file lacks |
| no visible twin | a proof near-identical to a sibling's. Caught `conservativity` against `conservativity_prop` at 0.92 |
| cascade cap (35%) | a target so load-bearing that punching it guts its module — `LJF.lean` loses 81%, `PLLKripke.lean` 54% |
| compiles | the punched module compiles clean, and each challenge elaborates with zero errors and exactly one `sorry` |
| blind header | no source file, no source line, no proof length, no difficulty |

Rebuild:

```bash
python3 prover-toolkit/challenge.py report
python3 prover-toolkit/challenge.py build --punch -o LaxLogic/ToolkitTest/Challenge
python3 prover-toolkit/challenge.py score <target>
python3 prover-toolkit/challenge.py retrieval-check
```

The punched `.olean` is written into Lake's own build root, so `lake env lean`
and `toolkit_cli.py check` resolve the import with no configuration. A
`lake clean` removes it; rebuild the set.

## What the set can and cannot measure

Punching moved the dependencies **into the corpus**, which is the point: with
prefix truncation 12 of 22 needed citations were Lean core and Mathlib, which
this index does not contain; here only 3 of 22 are. `retrieval-check` scores
recall@10 at 32% (6/19 in-corpus), against 20% for the truncated set.

Still open: two targets per module means the punched module they share is the
same file, so neither challenge leaks the other's proof — but a proposer who
reads the punched module will find every *other* lemma of that module, which is
what it is for.

Yield is low. Of seven source modules, `LJF.lean` and `PLLKripke.lean` exceed
the cascade cap, `FRJ/Erase.lean` is absent from this branch, and
`PLLG4ipComplete.lean`'s punched copy leaves a dangling `#`-command the cut
should have taken with it. Four targets from two modules is what survives; the
rejections are the acceptance criteria working, not silent failures.

## The retired set

`../Solved/` holds the first four challenge files with the proofs that closed
them (2026-08-30). They are a record, **not** a benchmark: that set was
contaminated by construction — `conservativity_prop`'s answer is written out
inside `Solved/conservativity.lean`, and three of the four needed nothing their
own file did not already contain.
